# TagField - タグ入力

レコードにタグを付ける・外す・候補から選ぶ・タグで探すためのフィールドです。画面ではチップ (× で外せる) で表示します。

## 画面での動き (先にこちら)

### 入力欄 (詳細画面・一覧の列)

- 付いているタグがチップで並ぶ。並びは**付けた順** (左が古い)
- 文字を打って Enter・「,」・「、」で確定すると、右端にチップが足される (設定でスペースでも確定できる)。前後の空白は落とす。空の入力は無視する
- タグ名は **200 文字まで** (入力欄・タグ付けモジュールの `Name`・DDL の列の長さが同じ値)
- × を押すとそのチップが外れる。入力欄が空のときに Backspace を押すと**右端のチップ**が外れる
- 入力欄の外へフォーカスが移ると、打ちかけの文字もタグになる (ウィンドウの切り替えでは確定しない)
- IME の変換中のキーは無視する。変換を確定する Enter でタグは作られず、確定後に「、」があれば分ける
- **同じタグは重ねない**。同一判定は**完全一致** (`AI` と `ai` は別のタグ)。表記の揺れは、入力中に既存のタグが候補に出ることで防ぐ
- タグが 1 つも無ければ、入力欄にプレースホルダが出る
- 閲覧 (読取専用) のときはチップだけを表示する
- 必須 (`IsRequired`) なら、タグが 1 つも無いと保存できない

### 候補

- 文字を打ち始めると、**同じモジュールのレコードに付いているタグ**のうち、打った文字を含むものが、**よく使われている順** (同じ件数なら名前順) に最大 10 件出る
- 既に付いているタグは出ない。打った文字に合うタグが無ければ何も出ない
- ↑↓ と Enter、またはクリックで選ぶ。選ばずに Enter を押せば、打った文字がそのままタグになる
- 候補はサーバーで絞る (全件を読まない)。候補の集計は**タグ付けモジュール**に対して走るので、効くのはタグ付けモジュールの読み取り条件 (UserRead / DataRead)。タグを付けるモジュール (親) の行の条件は自動では効かない。見せたくないタグがあるなら、タグ付けモジュールに読み取り条件を書く

### 保存

- 足し外しは何も書かない。**レコードを保存したときに一緒に書く** (1 つのトランザクション・レコードの書き込み権限)。保存せずにやめれば何も残らない
- レコードを消すと、そのタグも一緒に消える。消すのは本体の `DeleteTogether` (論理削除の親でも消える)。DDL の外部キー (ON DELETE CASCADE) は、SQL で直接レコードを消したときの保険

### 検索 (検索レイアウトに置いたとき)

- 同じチップの入力欄で、探すタグを 1 つ以上入れる。候補も同じように出る
- 横の選択で**すべて含む** (既定) / **いずれかを含む**を切り替える (`IsSimpleSearchParameter` で選択を隠し、既定で探す)
- タグ名は**完全一致** (「展示会」で「展示会2026」は当たらない。大文字小文字も区別する)
- 誰にも付いていないタグを入れると、「すべて含む」では 0 件、「いずれかを含む」ではそのタグは足しにならない
- タグを 1 つも入れていなければ絞らない (選択に関係なく)
- 条件はタグ名で持つので、画面に戻ったとき・URL を共有したときにも復元でき、後から付いたタグも反映される
- 親の検索画面に子のタグを置いたとき (例: 会社の検索に 社員.タグ)、「すべて含む」は**その会社の人のタグを合わせて**全部ある会社に合う (人ごとに全部持っている必要はない)。この 2 段 (一覧 → 一覧) の動きは Extras のテスト (会社 → 社員 → タグ、すべて含む / いずれか) で確かめている

### 一覧の列

- 一覧レイアウトにも置ける。ページの行の分のタグは、一覧の読み込みに同梱されて届く (行ごとの問い合わせは出ない)
- 編集できるセルではチップ + 入力欄、閲覧ならチップだけ

## データの形

```
tag_tests (タグを付けるモジュール)      tag_test_tags (タグ付け。タグを付けるモジュールごとに 1 つ)
├── id ◄──────────────────────────── owner_id   FK (レコードを消せば一緒に消える)
└── ...                               name       タグ名をそのまま持つ
                                      一意: (owner_id, name)   インデックス: name
```

- **タグ付け** (`TagLinkContractField` を置いたモジュール): 1 行 = あるレコードに付いたタグ 1 つ (タグを付けたレコードの Id + タグ名)。タグのマスタは無い
- **TagField**: タグ付けを子の一覧として持つ一覧フィールド。読み込み・保存 (レコードの保存に一緒に載る)・削除の連鎖・権限・編集履歴は本体の一覧と同じ仕組み

タグに色・説明・並び順を持たせたい、複数のモジュールでタグの一覧を共有したい、「決まったタグだけ」にしたい、が要件になったときに、そのための設定やモジュールを足します。今は入れていません。

## タグのセットアップ

- デザイナ: メニュー Tools > タグのセットアップ
- CLI (headless): `<designer.exe> tag-setup "<projectDir>" --target <Module> [--field Tags | --no-field] [--link-name <Module>Tags] [--link-table <table>] [--owner-column owner_id] [--data-source <name>] [--ddl-out <path.sql>]`

生成内容:

1. タグ付けモジュール (既定 `<Module>Tags`: `Id` / `OwnerId` / `Name` + `TagLinkContractField`)
2. タグを付けるモジュールに TagField (既定 `Tags`)。同名の TagField が結び付きなしで既にあれば、それを結び付ける
3. DDL: テーブル、(owner_id, name) の一意インデックス、name のインデックス、レコードへの外部キー (削除は連鎖)。既定の照合順序が大文字小文字を区別しない SQL Server / MySQL では、name の列に区別する照合順序を付ける (完全一致を DB でも成り立たせる。候補の Like も区別する)

**冪等**: 既存のモジュールは作らず、結び付き済みの TagField は触らない。DDL は自動実行されない (結果画面の実行ボタン、または `--ddl-out` のファイルを実行する)。
画面への配置はデザイナで行う (TagField を詳細・一覧・検索のレイアウトに置く)。

## デザイナー設定プロパティ

| プロパティ | デザイナ表示名 | 型 | 説明 |
|---|---|---|---|
| SearchCondition | 検索条件 | | タグ付けモジュールと、このレコードへの結び付き (`OwnerId.Value = Id.Value`)、並び (`Id` 昇順 = 付けた順)。セットアップが入れる |
| Placeholder | プレースホルダ | string | タグが無いときの入力欄のプレースホルダ |
| ConfirmOnSpace | スペースでも確定 | bool | スペースでもタグを確定する。既定 false (日本語のタグにはスペースが入ることがあるため) |
| IsRequired | 必須 | bool | 1 つ以上のタグ |
| IsSimpleSearchParameter | 簡易検索パラメータ | bool | 検索欄に一致の選択を出さない |
| SearchMatchDefaultValue | 検索の一致の既定 | enum | `All` = すべて含む (既定) / `Any` = いずれかを含む。画面で切り替えられる |

ほかに `DisplayName` / `OnDataChanged` / `OnSearchDataChanged` が使えます。一覧フィールドの表示用の設定 (ページング・行の追加削除ボタン等) はタグには関係ないので出ません。候補の件数 (10 件) は設定にしません。

## スクリプト API

| メンバ | 説明 |
|---|---|
| `Tags` | 付いているタグ (`List<string>`、付けた順、読み取り専用) |
| `AddTag(string tag)` | タグを足す。同じタグは重ねない。区切りを含めば分けて足す |
| `RemoveTag(string tag)` | タグを外す |
| `SetTags(List<string> tags)` | タグを置き換える (外したタグを外し、無いタグを足す) |
| `HasTag(string tag)` | そのタグが付いているか (完全一致) |
| `SearchTags` | 検索条件で選んでいるタグ (get / set) |
| `SearchMatch` | 検索の一致 (`TagSearchMatch.All` / `TagSearchMatch.Any`、get / set) |

タグの変更は、ほかのフィールドと同じくレコードを保存したときに書かれます。

スクリプトの `ModuleSearcher` で読んだレコードのタグを使うときは、`Select` で TagField を指定します (指定しないと子の一覧は読まれません):

```csharp
// 条件に合う人全員に、タグを足して保存する
void AddTag_OnClick()
{
    var ps = new ModuleSearcher<顧客企業社員>();
    ps.AddEqual(e => e.企業Id.Value, 企業Id.Value);
    ps.Select(e => e.Tags);
    var changed = new List<Module>();
    foreach (var p in ps.Execute())
    {
        if (p.Tags.HasTag("展示会2026")) continue;
        p.Tags.AddTag("展示会2026");
        changed.Add(p);
    }
    if (changed.Count > 0) this.Submit(changed);
}
```

## 配置の注意

- 一括ダウンロード / 一括更新 (BulkFileTransfer) はタグを扱いません (タグはレコードの列ではないため)
- 意味検索 (SemanticSearchField) の `SourceFields` に入れると、タグ名を並べた行が文章に入ります (保存時・再索引とも)

## CSS カスタマイズ

チップは `.tag-chip`、入力欄全体は `.tag-editor`、閲覧表示は `.tag-view` です。色や角丸を変えたいときは app.css で上書きしてください。

```css
.tag-chip { background: #eef3ff; border-color: #c7d7ff; }
```

# MailHistoryDetailContractField (メール送信明細契約)

メール送信明細モジュール (**1 宛先 1 行**) に1つ置き、「役割 → 自モジュールのフィールド名」のマッピングを
宣言するフィールド。UI もデータも持たない (DB列不要)。

送信履歴 (1 送信 1 行) の**明細**として、宛先ごとに**テンプレートを解決した後の**件名・本文と成否を残す。
「変数が正しく展開されたか」「誰に何を送ったか」を後から確認できる。

## 有効化 (任意)

- 履歴モジュール (MailHistoryContractField を置いたモジュール) に明細モジュールへの **List フィールド**を置き、
  履歴契約の役割 **`Details` (送信明細の一覧)** にそのフィールド名を設定する。一覧のバインドは `History.Value == Id.Value`
- `Details` が空なら明細は書かれない (既存の履歴モジュールはそのまま動く)
- **メールのセットアップ** (Tools > メールのセットアップ / CLI `mail-setup`) の「送信明細モジュールも生成」(既定 ON) で
  明細モジュール・履歴側の一覧・DDL が揃う (`--no-history-detail` / `--history-detail-name <名前>`)

## Design

| 役割 (表示名) | 内容 | 必須 |
|---|---|---|
| History (履歴) | Link → 履歴行 | ○ |
| To (宛先) | 宛先アドレス。デバッグ用リダイレクト送信でも**元の宛先** | ○ |
| Subject (件名 (解決後)) | その宛先で解決した件名 | - |
| Body (本文 (解決後)) | その宛先で解決した本文 (HTML 本文はそのまま文字列。複数行 Text 推奨) | - |
| IsSuccess (送信成否) | Boolean | - |
| Error (失敗理由) | 失敗時のエラー。成功時は空 | - |

- 必須以外は空にすれば「使わない」宣言 (その項目は記録しない)
- 必須役割が空・契約が名指ししたフィールドが不在なら、履歴と同様に**送信前の実行時エラー**になりメールを送らない
- リネームに自動追従。同じモジュールに複数置くとエラー

## 動作

- 単発送信 (MailField / 承認の通知メール): 宛先ごとに 1 行 (文面は同じ)
- 一斉送信 (BulkMailField): 宛先ごとに 1 行。件名・本文は**その宛先の変数で解決した実際の文面**
- 書き込みは履歴と同じサーバー内部経路 (操作ユーザーの書き込み権限に依存しない)。明細の失敗は送信を失敗させない
- 1 万通送れば 1 万行＋本文が入る。宛先アドレスと本文が残るので、履歴・明細モジュールの閲覧権限 (UserReadCondition) は絞ること

# EditHistoryField (編集履歴)

モジュールに 1 つ置くと、そのモジュールのレコードの保存 (作成・更新・削除) ごとに
レコード全体 (従属レコード = 明細やガントチャートのタスクなどを含む) のスナップショットが履歴モジュールへ記録される。
詳細画面には版の一覧 (変更されたフィールドだけを「旧 → 新」で表示) が出て、
「この版を表示」(その版のレコード全体を表示専用のダイアログで表示、変更フィールドを強調) と
「この版に戻す」(その版の内容を編集中のフォームへ反映。保存はユーザーが行う) が使える。
UI もデータも持たない設定運搬 + 閲覧フィールド (DB 列不要)。

## Design

- `HistoryModuleName`: 履歴を書く先のモジュール。そのモジュールには `EditHistoryContractField` を置く (無ければデザインチェックがエラー)。複数の対象モジュールで 1 つの履歴モジュールを共有してよい
- `LayoutName`: 「この版を表示」で使う自モジュールの詳細レイアウト。空 = 既定
- `PageSize`: 一度に読み込む版の数 (既定 20)。「さらに表示」で次を読む
- 同じモジュールに 2 つ置くとエラー

## 動作

- 記録はサーバー (`Codeer.LowCode.Blazor.Extras.Server` の `EditHistoryRecorder`)。アプリテンプレートの `CustomizedModuleDataIO.SubmitAsync` が結線済み。CSV / Excel の一括取込や API からの保存も同じ経路なので記録される (一括 INSERT 経路だけは Id が返らないため記録されない)
- 作成・更新は保存後の内容、削除は削除前の内容が 1 行になる。明細だけを変えた保存も親レコードの 1 版になる
- 版番号は保存せず、閲覧時に件数から採番する (古い方から 1, 2, ...)
- 履歴の読み取りは通常のモジュールデータ API = **履歴モジュールの閲覧権限 (UserRead / DataRead 条件) がそのまま効く**。履歴を見せたくないユーザーには履歴モジュールを読めなくすればよい。差分表示は対象モジュール側のフィールド権限 (PermissionField) で読めない項目を出さない。ただし履歴モジュールを直接読めるユーザーには Snapshot (JSON) の生の値が見える
- 「この版に戻す」は値フィールドを変更扱いで反映し (OnDataChanged スクリプトも動く)、明細は行 Id で突き合わせて更新・追加・削除する。物理削除済みの行は新しい行として追加される (Id は振り直し)。添付ファイルは対象外 (履歴に実体を持たない)。保存で確定し、その保存も 1 版として記録される
- 「この版に戻す」で無い明細行は、明細モジュールが論理削除なら Id を保って復活 (保存で確定)、物理削除なら新しい行になる
- 削除したレコードの履歴は履歴モジュールの一覧 (ChangeType = Delete) で見られる。復活は履歴モジュール側の EditHistoryRestoreButtonField
- 退避 (削除テーブルへの移動) とは併用できない (デザインチェック エラー)
- スナップショットの範囲は「レコード本体 ＋ 従属レコードの宣言 (IOwnedRecordsFieldDesign) の先」。何が従属かは各フィールドが決める (一覧は「親と一緒に消える一覧」、Gantt / Calendar / TaskBoard は自分の子レコード)。「この版に戻す」で子レコードまで戻る (一覧、Gantt / Calendar / TaskBoard / MarkerList)

## 配置の推奨

詳細レイアウトの右カラムかタブに置く。一覧レイアウトには置かない (行ごとに履歴を読むことになる)。

```json
{ "Name": "History", "TypeFullName": "Codeer.LowCode.Blazor.Extras.Designs.EditHistoryFieldDesign", "HistoryModuleName": "EditHistory" }
```

履歴モジュールの作り方は EditHistoryContractField のドキュメントを参照。

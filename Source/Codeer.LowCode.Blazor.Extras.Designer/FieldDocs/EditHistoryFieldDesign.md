# EditHistoryField (編集履歴)

モジュールに 1 つ置くと、そのモジュールのレコードの保存 (作成・更新・削除) ごとに
レコード全体 (従属レコード = 明細やガントチャートのタスクなどを含む) のスナップショットが履歴モジュールへ記録される。
詳細画面には版の一覧 (変更されたフィールドだけを「旧 → 新」で表示) が出て、
「この版を表示」(その版のレコード全体を表示専用のダイアログで表示、変更フィールドを強調) が使える。
そのダイアログの「編集中の内容をこの版に置き換える」(以下「この版に置き換える」) で、見ている版の内容を編集中のレコードに入れる (保存はユーザーが行う)。
データを持たない (DB 列不要)。

## セットアップ (履歴モジュールの自動生成)

動作には履歴モジュール (EditHistoryContractField を置いたモジュール) が必要。手で作らず**セットアップコマンドで生成する**:

- デザイナ: メニュー Tools > 編集履歴のセットアップ
- CLI (headless): `<designer.exe> edit-history-setup "<projectDir>" [--history-name EditHistory] [--data-source <name>]
  [--user-module <ユーザーモジュール>] [--user-name-field <表示名フィールド>] [--no-enum] [--no-pageframe] [--ddl-out <path.sql>]`

生成内容・冪等性・対象モジュール側の手順は EditHistoryContractField の「セットアップ」を参照。
履歴モジュールは全モジュールで 1 つ共有するので、2 つ目以降の対象モジュールでは実行不要 (このフィールドを置いて enum にメンバーを足すだけ)。

## Design

- `HistoryModuleName`: 履歴を書く先のモジュール。そのモジュールには `EditHistoryContractField` を置く。複数の対象モジュールで 1 つの履歴モジュールを共有してよい
- `LayoutName`: 「この版を表示」で使う自モジュールの詳細レイアウト。空 = 既定
- `PageSize`: 一度に読み込む版の数 (既定 20)。「さらに表示」で次を読む
- `ExcludedOwnedRecords`: 履歴に含めない従属レコード (下の「従属レコードの扱い」)
- `IndividuallyRecordedOwnedRecords`: 行ごとに記録する従属レコード (同上)
- `CanRestore`: 履歴からデータを戻せるか (既定 true)。false で「この版に置き換える」と、履歴モジュールの復活ボタン (EditHistoryUndeleteButtonField) でのこのモジュールのレコードの復活ができなくなる (サーバーも拒否する)。版の一覧・差分・「この版を表示」はそのまま

```json
{ "Name": "History", "TypeFullName": "Codeer.LowCode.Blazor.Extras.Designs.EditHistoryFieldDesign", "HistoryModuleName": "EditHistory" }
```

## 配置

- 詳細レイアウトの右カラムかタブに置く。詳細レイアウト専用で、一覧レイアウトには置けない
- 1 モジュールに 1 つ
- 履歴モジュール自身 (EditHistoryContractField を置いたモジュール) と Query モジュールには置けない
- 退避 (DeleteArchiveField = 削除テーブルへの移動) とは併用できない。履歴を入れるモジュールの削除は論理削除か物理削除にする (Id を保った復活が要るなら論理削除)
- 履歴モジュールは上の「セットアップ」で生成する (構成は EditHistoryContractField のドキュメント)

## 記録

- 記録はサーバー (`Codeer.LowCode.Blazor.Extras.Server` の `EditHistoryRecorder`)。アプリテンプレートの `CustomizedModuleDataIO` に登録済み。CSV / Excel の一括取込や API からの保存も同じ経路なので記録される (履歴対象モジュールは本体の一括 INSERT 経路を使わず 1 行ずつ入る)
- 作成・更新は保存後の内容、削除は削除前の内容が 1 行になる。変更種別は Add / Update / Delete / Restore (Restore は削除したレコードの復活)
- スナップショットの範囲は「レコード本体 ＋ 従属レコード」(子・孫も)。何が従属かは各フィールドが決める
  - 一覧: 親の画面で行を追加・更新・削除できる一覧と、親と一緒に消える一覧 (DeleteTogether)。参照するだけの一覧は入らない
  - 埋め込みモジュール (ModuleField): 参照している子レコード (DbColumn に子の Id を持つ埋め込み。DbColumn か ModuleName が無い埋め込みは対象外)
  - Gantt / Calendar / TaskBoard / MarkerList: 自分の子レコード。Gantt は依存関係も (`フィールド名:Dependencies`)
- 明細だけを変えた保存も親レコードの 1 版になる。従属レコードを行のモジュール側で個別に保存した変更は親の版にならない
- 自己参照の従属 (カテゴリ→子カテゴリが同じモジュール、部品表など) も深さのまま親の一部になる
- スナップショットは操作ユーザーの権限に関係なくレコード全体を記録する (読む人の権限は返すときに落とす)。NULL の列は null として入る。書き込み専用の列 (パスワードのハッシュなど) と PasswordField は入らない
- 添付ファイルはファイル名とキーだけ記録する。履歴を持つモジュールでは削除・差し替えで外れた添付の実体を本体が残すので、削除したレコードの復活では同じ添付が参照できる (DB 列格納の添付は戻らない)
- 版にならない保存: 何も保存しない送信 / 除外・行ごとの行だけを変えた保存 / ExecuteSqlField の Standalone でレコード自体が変わらなかった送信 / 保存後のレコードを特定できない・読めない保存 (ExecuteSqlField の Create タイミングで `NewId` が無いとき等。保存は成功し、理由はサーバーのログに出る)
- 履歴の書き込みに失敗すると保存も失敗する。履歴モジュール・契約が無い設計も保存が失敗する
- Id を変えた更新 (手入力 Id の書き換え・複合 Id の構成項目の変更) は、旧 Id の版を新しい Id に付け替える
- 承認フロー (ApprovalFlowField) と同じモジュールに置ける。申請・再申請は申請者の版になり、承認・却下・差し戻しなどの操作は版にならない (承認の記録は承認履歴の側)。承認フローの FK は差分に出ず、「この版に置き換える」でも触らない
- 自動保存 (AutoSubmitField) と同じモジュールに置ける。自動保存ごとに版になり、版一覧は自動保存のたびに読み直される。「この版に置き換える」の反映も自動保存される
- ExecuteSqlField の SQL が他のテーブルや他のレコードに書いたものは履歴に入らない (復元でも戻らない)

## 表示

- 画面を開いたときは件数 (「履歴 n 件」) だけを読み、「表示」を押してから版を読む。「閉じる」で件数の表示に戻る。未保存のレコードでは読まない
- 版番号は保存せず、閲覧時に件数から採番する (古い方から 1, 2, ...)。「閲覧者に見える版の中での連番」なので、履歴モジュールに閲覧条件があると人によって変わる。並びは DateTime 役割の降順 (同着・役割なしは Id の降順)
- 差分は変わった項目だけを「表示名: 旧 → 新」で出す。従属レコードは行 Id で突き合わせて 追加 / 削除 / 変更 の件数と行ごとの内訳 (行は行番号で示す)。作成・削除・復活の版は差分を出さない
- 「旧 → 新」の文字列を出すのは文字列・数値・真偽・日付時刻・候補・リンク・ファイル (名前) だけ。それ以外の型は「変更あり」とだけ出し、内容は「この版を表示」で見る
- 前の版が無い (履歴を取り始める前からあったレコードの最初の版)・前の版の内容がその人に見えないときは、差分を出さない
- 「この版を表示」の強調は、値フィールド = 緑の枠、明細 = 変更行の変わったセル / 追加行 / 削除行 (前の版の行を打ち消しで差し込む)、Gantt のタスク・カレンダーの予定・カード・マーカー = 項目単位 (追加 = 背景 / 変更 = 枠 / 削除 = 打ち消し)。差分のある項目が表示範囲に無ければ Gantt / Calendar はその項目の日 (月) へ移動する。保存ボタンと履歴フィールド自身は出ない

## この版に置き換える

- 「この版を表示」のダイアログのボタン「編集中の内容をこの版に置き換える」。`CanRestore` が true で、表示専用でないレコードの、最新でない版に出る (最新の版と削除の版には出ない)。確認は出ない (内容を見てから押す)
- 値フィールドを変更扱いで反映する (OnDataChanged スクリプトも動く)。保存で確定し、その保存も 1 版として記録される
- 従属レコードは行 Id で突き合わせて更新・追加・削除する (一覧、埋め込みモジュールの子、Gantt のタスクと依存関係 / Calendar / TaskBoard / MarkerList)
- 無い行は、行のモジュールが論理削除なら Id を保って復活 (保存に「その版からの取り消し」が同梱され、サーバーが戻す)、物理削除なら新しい行になる (Id は振り直し)
- サーバーが取り消すのは「版にあり・今は削除中・その人に差分として見えている」行だけ。戻せない行 (削除権限が無い等) が 1 つでもあれば保存全体が失敗する
- 対象外: システムフィールド、リンク越しの派生値、従属でない一覧、添付ファイル、書き込み権限のないフィールド、承認フローの FK。反映できる項目が 1 つも無いときはメッセージだけ出てフォームは変わらない
- 親の版に含める従属レコードの一覧は、メモリ内ページングか件数制限なしにする (サーバーページングは全件を差し替えられないので設計チェックが指摘する)

## 削除したレコード

- 削除したレコードの履歴は履歴モジュールの一覧 (ChangeType = Delete) で見られる
- 復活は履歴モジュール側の EditHistoryUndeleteButtonField
- 履歴行から対象レコードを開くのは本体の AnchorTagField (ModuleVariable = `ModuleName.Value` / IdVariable = `DataId.Value`)

## 権限

- 履歴の読み取りは通常のモジュールデータ API = 履歴モジュールの閲覧権限 (UserRead / DataRead 条件) がそのまま効く。履歴を見せたくないユーザーには履歴モジュールを読めなくすればよい (「履歴はありません」になる)
- 版の内容は返すときにサーバーが読む人の権限に落とす: 対象モジュールの読めない項目 (PermissionField)・読めない子モジュールの従属レコード・閲覧条件に合わない行を外す。対象モジュールを読めない人・行の閲覧条件 (DataReadCondition) に合わない版は内容が空になる (版は見えるが内容・差分・復元は無い)。履歴モジュールを直接読んでも生の値は見えない
- 行の閲覧条件は「レコード自身の列は版の内容、リンク越しの値は今のリンク先」で判定する。版の内容で判定できない条件 (版に無い一覧の行を使う 1:N) は読めない扱いになる
- 差分表示・復元はその人に返された内容だけを扱う (読めない項目は差分に出ず、復元でも触らない)

## 従属レコードの扱い

指定は従属宣言の名前 (通常はフィールド名)。子・孫・埋め込みの中は `Items.Details` のようにドット区切り。パスはフィールドのリネームに追従する。

- 含める (既定): 親の版に入り、差分・版表示・復元の対象
- `ExcludedOwnedRecords` (除外): 履歴に含めない。記録・差分・版表示・復元のすべてから外れる (件数の多い一覧向け)
- `IndividuallyRecordedOwnedRecords` (行ごとに記録): 親の版には入れず、親の保存に乗った行を行のモジュール自身の履歴に 1 行 1 版で記録する (親を削除したときは一緒に消える行の削除の版も作る)。行のモジュールに EditHistoryField が要る。差分・版表示・復元は行のモジュールの画面で行う
- 除外・行ごとの行だけを変えた保存は親の版にならない
- 含める先のモジュールが自分の EditHistoryField を持つと、このモジュール経由の編集がそのモジュールの履歴に残らないので設計チェックが指摘する。除外か行ごとに指定する
- 親に EditHistoryField が無いモジュール経由の編集は、自分の EditHistoryField を持つ従属レコードの行が自動で行ごとに記録される
- 同じ子モジュールに含める経路と行ごとの経路の両方があるときは、行ごとの指定が 1 つでもあれば行ごとに記録する (設計側で揃える)

## 設計チェック

| コード | 内容 |
|---|---|
| `EditHistoryFieldDesign:1` | 履歴モジュールに EditHistoryContractField が無い |
| `EditHistoryFieldDesign:2` | 同じモジュールに EditHistoryField が複数ある |
| `EditHistoryFieldDesign:3` | 退避 (DeleteArchiveField) と併用している |
| `EditHistoryFieldDesign:4` | 親の版に含める従属レコードが全件を持たない (サーバーページングの一覧。指摘の場所はその一覧フィールド) |
| `EditHistoryFieldDesign:5` | 除外・行ごとのパスが従属宣言に無い |
| `EditHistoryFieldDesign:6` | 行ごとに記録する先のモジュールに EditHistoryField が無い |
| `EditHistoryFieldDesign:7` | 同じパスを除外と行ごとの両方に書いている |
| `EditHistoryFieldDesign:8` | 履歴モジュール自身に置いている |
| `EditHistoryFieldDesign:9` | Query モジュールに置いている |
| `EditHistoryFieldDesign:10` | 一覧レイアウトに置いている |
| `EditHistoryFieldDesign:11` | 親の版に含める先のモジュールが自分の EditHistoryField を持つ |

## スクリプト

- `Expand()` / `Collapse()`: 版の一覧を展開する / 閉じる
- `Reload()`: 先頭から読み直す (展開前は件数だけ)
- `LoadMore()`: 次のページ (古い版) を読む
- `IsExpanded` / `IsLoaded` / `IsBusy` / `TotalCount` / `HasMore`

## 運用上の注意

- フィールドを足した・消した・改名した・型を変えた後の古い版は、今の設計で読む。今の設計に無い項目は差分・版表示・復元で無視される (フィールドの改名は追従しない)
- モジュールの改名にも追従しない (改名前の版は改名後のモジュールの履歴には出ない)
- EditHistoryField を外しても、記録済みの履歴は履歴モジュールに残る

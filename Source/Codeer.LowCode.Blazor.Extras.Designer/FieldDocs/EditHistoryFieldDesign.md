# EditHistoryField (編集履歴)

モジュールに 1 つ置くと、そのモジュールのレコードの保存 (作成・更新・削除) ごとに
レコード全体 (従属レコード = 明細やガントチャートのタスクなどを含む) のスナップショットが履歴モジュールへ記録される。
詳細画面には版の一覧 (変更されたフィールドだけを「旧 → 新」で表示) が出て、
「この版を表示」(その版のレコード全体を表示専用のダイアログで表示、変更フィールドを強調) と
「この版に戻す」(その版の内容を編集中のフォームへ反映。保存はユーザーが行う) が使える。
UI もデータも持たない設定運搬 + 閲覧フィールド (DB 列不要)。

## Design

- `HistoryModuleName`: 履歴を書く先のモジュール。そのモジュールには `EditHistoryContractField` を置く (無ければデザインチェックがエラー)。複数の対象モジュールで 1 つの履歴モジュールを共有してよい
- `LayoutName`: 「この版を表示」で使う自モジュールの詳細レイアウト。空 = 既定
- `PageSize`: 一度に読み込む版の数 (既定 20)。「さらに表示」で次を読む
- 同じモジュールに 2 つ置くとエラー

## 動作

- 記録はサーバー (`Codeer.LowCode.Blazor.Extras.Server` の `EditHistoryRecorder`)。アプリテンプレートの `CustomizedModuleDataIO.SubmitAsync` が結線済み。CSV / Excel の一括取込や API からの保存も同じ経路なので記録される (履歴対象モジュールは本体の一括 INSERT 経路を使わず 1 行ずつ入る)
- 作成・更新は保存後の内容、削除は削除前の内容が 1 行になる。明細だけを変えた保存も親レコードの 1 版になる。何も保存しない送信は版にならない
- 承認フロー (ApprovalFlowField) と同じモジュールに置ける。申請・再申請は申請者の版になり、承認・却下・差し戻しなどの操作は版にならない (承認の記録は承認履歴の側)。承認フローの FK は差分に出ず、「この版に戻す」でも触らない
- 自動保存 (AutoSubmitField) と同じモジュールに置ける。自動保存ごとに版になり、版一覧は自動保存のたびに読み直される。「この版に戻す」の反映も自動保存される
- 版番号は保存せず、閲覧時に件数から採番する (古い方から 1, 2, ...)
- 履歴の読み取りは通常のモジュールデータ API = **履歴モジュールの閲覧権限 (UserRead / DataRead 条件) がそのまま効く**。履歴を見せたくないユーザーには履歴モジュールを読めなくすればよい。スナップショットは権限に関係なくレコード全体を記録し、返すときにサーバー (EditHistoryRecorder.GetListAsync) が読む人の権限に落とす (対象モジュールの読めない列と読めない子モジュールの従属レコードを外す。対象モジュールを読めない人・行の閲覧条件 (DataReadCondition) に合わない版は空)。履歴モジュールを直接読んでも生の値は見えない。差分表示・復元もその人に返された内容だけを扱う
- 「この版に戻す」は値フィールドを変更扱いで反映し (OnDataChanged スクリプトも動く)、明細は行 Id で突き合わせて更新・追加・削除する。物理削除済みの行は新しい行として追加される (Id は振り直し)。添付ファイルは対象外 (履歴に実体を持たない)。保存で確定し、その保存も 1 版として記録される
- 「この版に戻す」で無い明細行は、明細モジュールが論理削除なら Id を保って復活 (保存に「その版からの取り消し」が同梱され、サーバーが版のスナップショットから戻す)、物理削除なら新しい行になる。反映できる項目が 1 つも無いとき (書き込み権限のない項目・添付ファイルだけ、など) はメッセージだけ出てフォームは変わらない
- 「この版を表示」の強調は、値フィールド = 緑の枠、明細 = 変更行の変わったセル / 追加行 / 削除行 (前の版の行を打ち消しで差し込む)、Gantt のタスク・カレンダーの予定・カード・マーカー = 項目単位 (追加 = 背景 / 変更 = 枠 / 削除 = 打ち消し)。差分のある項目が表示範囲に無ければ Gantt / Calendar はその項目の日 (月) へ移動する
- 削除したレコードの履歴は履歴モジュールの一覧 (ChangeType = Delete) で見られる。復活は履歴モジュール側の EditHistoryUndeleteButtonField (削除できる人にだけ出る。サーバーが版のスナップショットからレコード全体を戻す)、履歴行から対象レコードを開くのは本体の AnchorTagField (ModuleVariable = ModuleName.Value / IdVariable = DataId.Value)
- 版番号は「閲覧者に見える版の中での連番」(履歴モジュールに閲覧条件があると人によって変わる)。変更種別は Add / Update / Delete / Restore
- 履歴モジュール自身 (EditHistoryContractField を置いたモジュール) と Query モジュールには置けない (EditHistoryFieldDesign:8 / :9)
- 退避 (削除テーブルへの移動) とは併用できない (デザインチェック エラー)
- スナップショットの範囲は「レコード本体 ＋ 従属レコードの宣言 (IOwnedRecordsFieldDesign) の先」。何が従属かは各フィールドが決める (一覧は「親の画面で行を追加・更新・削除できる一覧」と「親と一緒に消える一覧」。参照するだけの一覧は入らない。Gantt / Calendar / TaskBoard は自分の子レコード。Gantt は依存関係も `フィールド名:Dependencies` として宣言する)。「この版に戻す」で子レコードまで戻る (一覧、Gantt のタスクと依存関係 / Calendar / TaskBoard / MarkerList)
- 対象モジュールの従属レコード (明細の一覧など。子・孫・埋め込みの中も) はランタイムで全件を持つ設定にする: 一覧はメモリ内ページングか件数制限なし。サーバーページングの一覧は「この版に戻す」で全件を差し替えられないので設計チェックが指摘する (EditHistoryFieldDesign:4)
- 埋め込みモジュール (ModuleField) は本体が子レコードを従属として宣言する (参照 = DbColumn の子 Id。DbColumn が無い埋め込みは宣言しない) ので明細と同じ: 子レコード 1 行の一覧として版に入り、差分は行 1 の項目ごと、版表示で子の変わった項目が強調され、「この版に戻す」で子の項目 (と親の参照) も戻る

## 従属レコードの扱い

- `ExcludedOwnedRecords`: 履歴に含めない従属レコード (従属宣言の名前。子・孫・埋め込みの中は "Items.Details")。記録・差分・版表示・復元のすべてから外れる (件数の多い一覧向け)。除外した行だけを変えた保存は親の版にならない
- `IndividuallyRecordedOwnedRecords`: 行ごとに記録する従属レコード (同じくパス)。親の版には入れず、親の保存に乗った行を行のモジュール自身の履歴に 1 行 1 版で記録する (親を削除したときは一緒に消える行の削除の版も作る)。行のモジュールに EditHistoryField が要る (無ければ EditHistoryFieldDesign:6)。行だけを変えた保存は親の版にならない
- 存在しないパスは EditHistoryFieldDesign:5、同じパスを両方に書くと EditHistoryFieldDesign:7。除外・行ごとの一覧は全件性のチェック (EditHistoryFieldDesign:4) の対象外。パスはフィールドのリネームに追従する

## 配置の推奨

詳細レイアウトの右カラムかタブに置く。一覧レイアウトには置かない (行ごとに履歴を読むことになる)。

```json
{ "Name": "History", "TypeFullName": "Codeer.LowCode.Blazor.Extras.Designs.EditHistoryFieldDesign", "HistoryModuleName": "EditHistory" }
```

履歴モジュールの作り方は EditHistoryContractField のドキュメントを参照。デザイナの Tools > 編集履歴のセットアップ (CLI `edit-history-setup`) で
契約・復活ボタン・対象レコードリンク・検索レイアウト・対象モジュール enum・ページリンク込みの履歴モジュールと DDL を生成できる。

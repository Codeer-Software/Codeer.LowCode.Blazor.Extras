# EditHistoryUndeleteButtonField (編集履歴 復活ボタン)

削除されたレコードを履歴から復活させるボタン。履歴モジュール (EditHistoryContractField を置いたモジュール) の
詳細レイアウトに置く。

## Design

- `Text`: ボタンの文言。空なら「このレコードを復活」

```json
{ "Name": "UndeleteButton", "TypeFullName": "Codeer.LowCode.Blazor.Extras.Designs.EditHistoryUndeleteButtonFieldDesign" }
```

## ボタンが出る条件

次をすべて満たす履歴行の詳細にだけ出る。

- ChangeType が Delete (削除の版)
- その版がそのレコードの最新の版 (復活済み・変更済みのレコードの古い削除の版には出ない)
- 対象モジュール (履歴行の ModuleName) がある
- 対象モジュールで削除できる人 (CanDelete と UserRead / UserWrite 条件)

## 動作

- クライアントは「削除の版の履歴行の Id」だけを送り、サーバー (EditHistoryRecorder) がその版のスナップショットからレコード全体を 1 トランザクションで戻す
- サーバーも同じ条件を確かめる: 最新の版が削除であること、今そのレコードが無い (削除中) こと。満たさなければ失敗する (同じレコードをもう 1 件作らない)
- 対象モジュールが**論理削除** (LogicalDelete / DeletedAt / Deleter のどれかがある) なら、
  レコードと、親と一緒に消えた従属レコード (子・孫) を Id を保って「削除の取り消し」で戻す。Id はそのままなので、そのレコードへのリンクは切れない。
  子の行は親の削除が子を消すときと同じく、子モジュールの CanDelete だけを見る (ユーザーの権限・行の条件は見ない)。物理削除モジュールの子は作り直す
- 対象モジュールが**物理削除**なら、スナップショットから作り直す。手入力 Id (複合 Id) のモジュールは元の Id で作る。
  自動採番のモジュールは新しい Id になり、子も親の新しい Id で作り直す。このとき旧 Id の版は新しい Id に付け替えられ、復活したレコードの履歴は最初から繋がる。
  そのレコードを Id で参照していた他のレコードのリンクは繋がらない
- 埋め込みモジュール (ModuleField) の子は親の削除では消えないので、親の参照を版の子に戻す (子も消えていれば版の内容で作り直す)
- 対象モジュールの EditHistoryField で除外した従属レコードは版に無いので戻らない。行ごとに記録する従属レコードは、各行の削除の版から個別に復活する
- 添付ファイルは、削除で外れた実体を本体が残しているので同じ添付を参照できる (DB 列格納の添付は戻らない)。書き込み専用の列 (パスワードのハッシュなど) は版に無いので、作り直しでは戻らない
- 復活は ChangeType = Restore の版として記録される
- 権限は削除と同じ: 対象モジュールの CanDelete と UserRead / UserWrite 条件に加え、行の条件 (DataRead / DataWrite) を削除前の内容に当てる。
  権限が無ければ失敗のメッセージが出る
- 復活後はそのレコードの詳細に遷移する (自動採番の物理削除は作り直した新しい Id)

- `IsBusy` / `ButtonText`
